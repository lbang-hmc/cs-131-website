# Module 08.3: Self-Application, Recursion, and Fixed Points

In Module 08.1, we learned that the lambda calculus has only three kinds of expressions: variables, abstractions, and applications.

In Module 08.2, we discovered that these same expressions can encode Booleans, pairs, lists, and numbers. In Lab 08, you build your own operations on those representations.

Now we face another surprising challenge.

In Haskell, a recursive function can call itself **by name**:

```haskell
factorial :: Integer -> Integer
factorial n =
  if n == 0
    then 1
    else n * factorial (n - 1)
```

But in pure lambda calculus, functions are *anonymous*. We cannot simply define a function by assigning a name to itself inside its body. Names such as `True`, `Pair`, or `Succ` in `.lc` files are abbreviations, not a new recursive-definition construct.

So how can recursion possibly work?

This module develops an answer through **self-application**, **fixed points**, and the **Y combinator**. Along the way, we'll connect the problem to self-reference in mathematical logic and recover one of the main insights behind lambda calculus as a general model of computation.

**By the end of this module, you should be able to** describe sets as functions, explain the self-reference problem in Russell's paradox, recognize self-application, define a fixed point, follow the key reduction establishing the Y combinator's fixed-point property, and explain how a nonrecursive *function generator* can give us a recursive function.

## A Function Doesn't Have to Be a Named Thing

Think about the Haskell function:

```haskell
square x = x * x
```

We can also write it anonymously:

```haskell
\x -> x * x
```

That is already an important theme of our course: functions are **values**, not merely chunks of code with names attached.

But consider the recursive function:

```haskell
factorial n =
  if n == 0
    then 1
    else n * factorial (n - 1)
```

If we remove its name, we get an unfinished definition:

```haskell
\n ->
  if n == 0
    then 1
    else n * ??? (n - 1)
```

What goes in place of `???`?

We cannot say `factorial` because that name is precisely what we removed.

This is the puzzle:

> **How can an anonymous function arrange to call itself?**

Before answering it, let's examine what happens when expressions are allowed to *refer to themselves*.

## Another Encoding: Sets as Functions

We have already encoded Booleans, pairs, and numbers. Here's another useful example.

A **set** can be represented by its **membership test**.

For instance, the set of even integers could be represented in Haskell by:

```haskell
isEven :: Integer -> Bool
isEven n = even n
```

The function answers whether a given value belongs to the set:

```haskell
isEven 4  -- True
isEven 5  -- False
```

In this representation, a set is simply a function that returns a Boolean.

If `s` represents a set, then conceptually:

```text
s x  →*  True     when x is in the set
s x  →*  False    when x is not in the set
```

In pure lambda calculus, even these Booleans are functions, as we learned in Module 08.2.

### Set operations become function operations

With sets-as-membership-tests, the empty set and universal set have simple Haskell representations:

```haskell
empty _ = False
universe _ = True
```

The complement of a set flips its answers:

```haskell
complement s x = not (s x)
```

And the union of two sets asks whether a value belongs to either one:

```haskell
union s t x = s x || t x
```

A lambda-calculus encoding follows the same structure using the `True`, `False`, `Not`, and `Or` functions we already have.

Notice the pattern: **represent a value by a function that answers the question we care about**. This is the same general approach that gave us Church Booleans and Church numerals.

We won't need to build a full set library. This representation is useful here because it leads to an interesting question about self-reference.

## Russell's Paradox and Self-Reference

Imagine a collection of library catalogs. Some catalogs list themselves as one of the books in their collection; other catalogs do not.

Now imagine making **the catalog of all catalogs that do not list themselves**.

Call this special catalog `R`.

Should `R` list itself?

- If `R` **does** list itself, then it violates its own rule, because it is supposed to list only catalogs that **do not** list themselves.
- If `R` **does not** list itself, then it seems to meet the rule for being listed, so it **should** list itself.

This is the core of **Russell's paradox**, commonly expressed in set notation as:

```text
R = { x | x ∉ x }
```

with the question:

```text
R ∈ R  ?
```

Russell's paradox showed that an unrestricted idea of “any definable collection is a set” leads to contradiction. Modern axiomatic set theories restrict which collections can be formed.

### The connection to lambda calculus

In our function-based encoding, membership looks like function application:

```text
(R x)
```

And since lambda calculus allows **any expression to appear in function position or argument position**, it allows:

```text
(R R)
```

A formal expression inspired by Russell's construction is:

```text
R = (λx.(Not (x x)))
```

The intended reading is: given `x`, ask whether `x` belongs to itself, then negate the answer.

Now apply `R` to itself:

```text
(R R)

→β (Not (R R))
```

The question reappears inside its own negation.

**Important distinction:** Russell's paradox concerns an inconsistent unrestricted set-forming principle. In the untyped lambda calculus, this self-referential term is not automatically a proof of logical contradiction. Its reduction behavior can instead fail to reach a normal form. We'll use the example to motivate **self-reference**, not to claim that lambda calculus is inconsistent.

On the right, the lambda-calculus version: (R R) with a β arrow to (Not (R R)), where the (R R) inside points back to the start. ## Self-Application Is Allowed

Consider the ordinary lambda expression:

```text
(λx.(x x))
```

This is a function whose body applies its argument **to itself**.

Now apply that function to another expression `g`:

```text
((λx.(x x)) g)
```

β-reduction substitutes `g` for *both* occurrences of `x`:

```text
   ((λx.(x x)) g)
→β (g g)
```

There is nothing special about `g`. It could itself be a function.

### A famous looping expression

Recall from Module 08.1:

```text
Ω = ((λx.(x x)) (λx.(x x)))
```

Reducing it gives the same expression back:

```text
Ω →β Ω →β Ω →β ...
```

This is a perfectly valid lambda-calculus expression, even though its reduction does not terminate.

We have discovered that self-application can **recreate part of an expression**.

Now let's ask whether we can use that ability more productively.

---

## Using Self-Application to Create More Work

Suppose `f` is some function that we want to keep applying.

Compare two small functions:

```text
(λx.(x x))
```

and:

```text
(λx.(f (x x)))
```

The second one does something extra: it **applies `f` to the result of the self-application**.

To make the structure readable, let's temporarily give it the abbreviation:

```text
A = (λx.(f (x x)))
```

What happens when we apply `A` to itself?

```text
(A A)
```

Expand the first `A` as the function:

```text
((λx.(f (x x))) A)
```

β-reduction replaces both occurrences of `x` with `A`:

```text
(A A) →β (f (A A))
```

The remarkable thing is that **`(A A)` has reappeared inside the result**!

The expression has reproduced itself under one extra application of `f`.

If we unfold it again, we get a pattern:

```text
(A A)
  →β (f (A A))
  →* (f (f (A A)))
  →* (f (f (f (A A))))
  ...
```

This is not yet a useful factorial computation. We are just looking at the basic mechanism.

But we now have exactly the kind of ingredient recursion needs: **an expression that can give itself back to a function**.

## Fixed Points: A Familiar Mathematical Idea

Before introducing another lambda expression, let's recall a simpler concept.

A **fixed point** of a function `g` is a value `x` such that:

```text
g x = x
```

The function leaves that value unchanged.

For example, consider:

```text
g(x) = 20 - x²
```

Then:

```text
g(4) = 20 - 16 = 4
```

So `4` is a fixed point. In fact, `-5` is another one, since `20 - 25 = -5`.

A fixed point need not be the number zero, and a function can have more than one fixed point.

### What if the fixed point is itself a function?

We have become used to higher-order functions: functions can accept other functions as arguments and return functions as results.

So imagine that `F` takes a **function** as its argument and returns a **function**.

We might want to find a function `h` with the property:

```text
F h = h
```

In other words, `h` is a fixed point of the higher-order function `F`.

For recursion, that equation is extremely useful: it says that `h` behaves like the result of feeding `h` back into the construction `F`.

A **fixed-point combinator** is a lambda expression that can construct such fixed points.

## The Y Combinator

Now return to the self-application pattern from earlier in this module.

We had:

```text
A = (λx.(f (x x)))
```

and observed:

```text
(A A) →β (f (A A))
```

That is exactly the fixed-point behavior we were seeking! The self-applied expression behaves like an input that stays the same when passed to `f`, at least up to β-reduction.

All we need is a function that, when given an arbitrary `f`, constructs that self-applied expression.

The result is the famous **Y combinator**:

```text
Y = (λf.((λx.(f (x x))) (λx.(f (x x)))))
```

This looks complicated primarily because it repeats a small expression twice. Let's take it apart carefully.

### Step 1: give Y a function F

Write:

```text
(Y F)
```

Expand the definition of `Y`:

```text
((λf.((λx.(f (x x))) (λx.(f (x x))))) F)
```

### Step 2: perform the first β-reduction

Substitute `F` for `f`:

```text
((λx.(F (x x))) (λx.(F (x x))))
```

For readability, let:

```text
A = (λx.(F (x x)))
```

Now we have:

```text
(A A)
```

### Step 3: perform the self-application

As we already learned:

```text
(A A) →β (F (A A))
```

But `(A A)` is precisely the self-applied expression obtained when we unfolded `(Y F)`.

So, up to β-reduction/β-equivalence, we've shown the defining property:

```text
Y F  =β  F (Y F)
```

Read this as:

> **The result of applying Y to F is a fixed point of F.**

The symbol `=β` means the two expressions are equivalent under β-reduction. We are not claiming that the strings of characters are literally identical.

![Four stages left to right: Y F, then A A, then F (A A), then F (Y F). F is in one color, A = λx.(F (x x)) in a second color, and the self-application A A is highlighted in a third. The first two arrows are β-reduction steps. The last step is marked =β because Y F also reduces to A A, so F (A A) and F (Y F) are equivalent rather than textually identical. A small loop arrow around A A shows it reappearing inside its own result.](img/08.3/y-combinator.svg){ width="800" }

### One important qualification

The Y combinator shown here works as a fixed-point construction in the untyped lambda calculus under reductions that allow the recursive argument to remain unexpanded until needed (as with normal-order reduction).

If a language always evaluates every function argument before applying the function, naively using this expression can cause immediate divergence. That does **not** mean recursion is impossible in eager languages. It means that the details of the fixed-point construction must accommodate the evaluation strategy.

For this course, focus on the reduction property and on how it provides a way to express recursion without named recursive definitions.

## Getting a Recursive Function from a Nonrecursive Function

Let's return to our original factorial puzzle.

In Haskell, we ordinarily write:

```haskell
factorial n =
  if n == 0
    then 1
    else n * factorial (n - 1)
```

The obstacle to making this anonymous is the recursive call to `factorial`.

### A useful trick: make the recursive call a parameter

Instead of requiring the function to call *itself by name*, imagine that it **receives a function it is allowed to call**.

```haskell
factorialStep rec n =
  if n == 0
    then 1
    else n * rec (n - 1)
```

`factorialStep` is **not recursive**. It never calls `factorialStep` or `factorial`.

Instead, it accepts an ordinary parameter named `rec`, which is supposed to handle the smaller problem.

Its type is conceptually:

```haskell
factorialStep :: (Integer -> Integer) -> (Integer -> Integer)
```

Given a function from integers to integers, it produces a new function from integers to integers.

### The special function we want

Suppose we could find a function `h` such that:

```text
factorialStep h = h
```

Then `h` behaves exactly as factorial should:

```text
h n = if n == 0 then 1 else n * h (n - 1)
```

That is the original recursive equation, but we obtained it by finding a **fixed point** of the nonrecursive function generator `factorialStep`.

And now we know an operation whose purpose is to produce fixed points:

```text
Y
```

### The same idea in lambda-calculus notation

We can express a factorial-like function generator using our existing encoded operations. The following uses the `IsZero`, `Times`, and `Pred` encodings (HW 8's starter file provides all three, along with `Y`):

```text
FactorialStep =
  (λrec.(λn.(((IsZero n) 1) ((Times n) (rec (Pred n))))))
```

Read the body as:

```text
if n is zero:
    return 1
else:
    return n * rec(n - 1)
```

The important part is the outer parameter `rec`: this generator is **not itself recursive**. It merely describes what one layer of a factorial computation should do, *given* an appropriate function for the recursive case.

Applying the fixed-point combinator to the generator gives the recursive function:

```text
(Y FactorialStep)
```

The details of the evaluation strategy matter, as noted above, but the conceptual recipe is the key result.

### The general recipe

Given a recursive function you would normally write by name:

1. Replace its recursive self-reference with a **new function parameter**.
2. Treat the resulting nonrecursive definition as a higher-order *function generator*.
3. Find a fixed point of that generator using a combinator such as `Y`.
4. The fixed point behaves like the original recursive function.

This is a genuinely different way of thinking about recursion: **recursion can be derived from ordinary function application rather than taken as a primitive language feature**.

## Why the Connection to Church and Turing Matters

We have now seen something that would have seemed implausible at the beginning of Module 08.1.

Using only functions, variables, and application, we have described:

- ways to choose between alternatives (Booleans),
- ways to store and recover data (pairs and lists),
- ways to represent repeated operations (Church numerals),
- and ways to express recursion without named recursive definitions (fixed points).

This does not mean that the lambda calculus is a pleasant replacement for a modern programming language. Its simplicity can make ordinary tasks surprisingly awkward.

Instead, it gives us an extraordinarily small **model of computation**. By analyzing its few rules, we can investigate what computation fundamentally requires, apart from the many conveniences of particular languages.

That is why lambda calculus belongs alongside Turing machines in the history of computability, and why its ideas appear in functional programming, language semantics, compiler design, and beyond.

## What to Carry Forward

**Self-application** makes it possible for expressions to regenerate structure that refers back to the original computation.

A **fixed point** of a function `F` is something unchanged by applying `F` (up to the relevant notion of equivalence).

The **Y combinator** constructs such a point in untyped lambda calculus:

```text
Y F =β F (Y F)
```

A **recursive definition** can be factored into a nonrecursive higher-order generator. Taking a fixed point of that generator provides the required recursion.

All of this happens without extending lambda calculus beyond its three original expression forms.
