## Background: From AST to Python

Instead of parsing text, you write piq programs directly as Haskell values. For example, this piq program:

```
x = 20
square x
move right 30
circle x / 2
```

is written this week as the Haskell value:

```haskell
Program [] [ Assign "x" (Num 20)
           , Square (Var "x")
           , Move Rt (Num 30)
           , Circle (Div (Var "x") (Num 2)) ]
```

and your compiler turns it into lines of Python like `pen_up()`, `pen_down()`, and `move_rel(-10.0, -10.0)`. The provided infrastructure wraps those lines into a runnable Python program, which can draw a preview picture on your computer, or drive the real plotter:

```text
    AST (a Haskell value)
        |
        |  YOUR WORK: evaluate expressions, compile statements
        v
    [String]  (lines of Python: pen_up(), pen_down(), move_rel(dx, dy))
        |
        |  PROVIDED: wrap into a complete Python program
        v
    python/<name>.py  ──>  preview picture  python/<name>.png
                     └──>  the real pen plotter (in the lab)
```

The work is split into many small steps. The starter repo's own `ASSIGNMENT.md` walks through every one of them, with a **Check your work** box after each step telling you exactly what to type and exactly what you should see — work through it from the top once you've cloned the repo. This page gives you the background and the shape of each part.

## The piq Language

**Expressions** (`Expr`) are arithmetic on numbers (every value in piq is a `Double`):

| Abstract syntax | Meaning |
|---|---|
| `Num 3` | the number 3 |
| `Var "x"` | the value of variable `x` |
| `Add e1 e2`, `Sub e1 e2`, `Mul e1 e2`, `Div e1 e2` | `e1 + e2`, `e1 - e2`, `e1 * e2`, `e1 / e2` |

For example, `Add (Var "x") (Mul (Num 5) (Num 2))` means `x + 5 * 2`. A negative number needs parentheses in Haskell: `Num (-5)`.

**Directions** (`Direction`) are page-relative: `Lt`, `Rt`, `Up`, `Dn`. "Up" always means toward the top of the page. There is no turning.

**Statements** (`Stmt`):

| Abstract syntax | Meaning |
|---|---|
| `Assign "x" e` | `x = e`: give variable `x` the value of `e` |
| `Dot` | a dot at the current position |
| `Square s` | a square with side `s`, **centered** on the current position |
| `Rectangle w h` | a `w` × `h` rectangle, centered on the current position |
| `Circle r` | a circle of radius `r`, centered on the current position |
| `Move d n` | travel `n` mm in direction `d` **without** drawing |
| `Line d n` | draw a line `n` mm long in direction `d` |
| `For "i" e1 e2 body` | repeat `body` (a list of statements) for `i` from `e1` to `e2` |
| `Call "f" args` | run procedure `f` with the given argument expressions |

A **program** is `Program defs stmts`: procedure definitions (`ProcDef name params body`), then the statements to run.

## What the Compiler Produces

Your compiler produces a list of strings, `[String]`, one line of Python each. Only three kinds of line are ever needed — you don't write the strings yourself, you use these functions:

| Haskell | Python line | Meaning |
|---|---|---|
| `penUp` | `pen_up()` | raise the pen |
| `penDown` | `pen_down()` | lower the pen onto the paper |
| `moveRel dx dy` | `move_rel(dx, dy)` | travel `dx` mm right and `dy` mm up. It **draws if the pen is down**, and doesn't if it's up |

The rules that give piq its meaning (its "spatial semantics"):

- **There is a current position.** Moves are relative to it, and it changes as the pen travels.
- **Closed shapes** (`Dot`, `Square`, `Rectangle`, `Circle`) are **centered** on the current position, and **leave the current position unchanged**: the pen ends exactly where it started. That makes shapes easy to place: move to a spot, then draw a shape around it.
- **`Move`** travels without drawing; **`Line`** draws and leaves the pen at the far end. Both change the position.
- **Between statements, the pen is always up.** Every statement that lowers the pen raises it again before it ends — no statement ever has to worry about what came before it.

## Part 1: Expressions and Environments

You've written an arithmetic evaluator before — this one adds **variables**. An environment is a lookup table from variable names to values:

```haskell
type Env = Map.Map Name Double
eval :: Env -> Expr -> Double
```

!!! example
    ```
    ghci> eval (assignVar "x" 10 emptyEnv) (Add (Var "x") (Num 5))
    15.0
    ghci> lookupVar "x" emptyEnv
    *** Exception: undefined variable: x
    ```

You'll implement variable lookup, the four arithmetic operators, and division's error case (dividing by an expression that evaluates to 0 — not just the literal `0`).

**Testing:** `runghc -itest test/Spec.hs --match "Step 1.N"` for one step, or `make part1` for the whole part.

## Part 2: Basic Drawing

Now the compiler proper:

```haskell
compileStmt :: ProcEnv -> Env -> Stmt -> (Env, [String])
```

It takes the current environment and a statement, and returns the environment **after** the statement (unchanged, for drawing statements) along with the statement's Python lines. You'll implement `Move`, `Line`, `Square`, and `Rectangle`, each via a small helper (`moveCode`, `squareCode`, …) that builds Python lines from plain numbers.

A square, for example, is drawn in three stages: travel to a corner with the pen up, draw the four sides in one continuous stroke, and travel back to the centre — the tests check that it's exactly one stroke, and that the pen ends back at the centre, pen up.

**Testing:** `make part2`.

## Part 3: Circles

A plotter can only draw straight lines, so a circle is drawn as a 36-sided regular polygon. Given the centre at the current position, corner `k` sits at angle `θₖ = 2πk / 36`, at `(r·cos θₖ, r·sin θₖ)`.

!!! example
    The move from corner `k` to corner `k + 1` is the relative move:
    ```
    dx = r·cos θₖ₊₁ − r·cos θₖ          dy = r·sin θₖ₊₁ − r·sin θₖ
    ```
    Computing each step from its two corners directly (not by accumulating previous steps) makes the path close exactly.

**Testing:** `make part3`.

## Part 4: Assignment and Statement Sequences

So far every statement has been compiled on its own, starting from no variables — which can't handle `x = 10; square x`, since the square needs to know what the *previous* statement assigned. This part makes statements run **in sequence**, passing the environment from each one to the next:

```haskell
compileStmts :: ProcEnv -> Env -> [Stmt] -> (Env, [String])
```

`Assign` itself produces no Python — it just returns a new environment. The recursive case of `compileStmts` is the real work: compile the first statement, then compile the rest **in the environment it left behind**. Once this part is done, you can compile and preview whole programs, not just standalone statement lists.

**Testing:** `make part4`.

## Part 5: Loops

`For "i" from to body` repeats `body` once per whole number from `from` to `to`, inclusive, with `i` bound to that number each time. A few rules make this precise:

- both bounds must be whole numbers, evaluated once, before the loop starts;
- if `from` is bigger than `to`, the body runs zero times;
- assignments to *other* variables inside the body persist after the loop;
- but the **loop variable itself is local to the loop** — afterward it gets back whatever value (or absence of one) it had before, so a loop never clobbers a same-named variable outside it.

That last rule is why you'll implement `saveVar`/`restoreVar` alongside `compileLoop`, which is shaped much like `compileStmts`: the environment flows from one iteration into the next, which is how something like a running total can accumulate across the loop.

**Testing:** `make part5`.

## Part 6: Procedures

A procedure is a named, parameterized list of statements, defined at the top of a program and invoked with `Call "f" args`. A call:

1. looks up the procedure, and checks its argument count matches;
2. evaluates all arguments in the **caller's** environment;
3. builds a **local environment** — the caller's, with each parameter bound to its argument's value;
4. compiles the body in that local environment, keeping only its code;
5. lets the caller carry on with its **own, unchanged** environment — nothing the procedure assigns escapes it.

Recursion isn't supported (a procedure calling itself, directly or indirectly, isn't a valid piq program).

**Testing:** `make part6`.

## Common Pitfalls

- **`"TODO (Part N): …"` in a test failure** means a function you haven't written yet is being used — check which part it's from; later parts are *expected* to fail until you get there.
- **Forgetting `:reload`** in GHCI after editing `PiqEvaluation.hs`.
- **Up is positive.** `offset Up` must give a positive `dy`.
- **A closed shape that doesn't return to its centre** makes everything after it land in the wrong place.
- **Returning the wrong environment:** drawing statements return the `env` they were given; `Assign` returns the new one; a call returns the **caller's** `env`, not the procedure's.
- **Evaluating in the wrong environment:** a loop's bounds and a call's arguments are evaluated in the environment from *before* the loop or call.
- **Forgetting `restoreVar`** after a loop, so the loop variable leaks out.
- **Error messages must match exactly**, including spacing: `undefined variable: x`, `division by zero`, `non-integral loop bound: 2.5`, `procedure f expects 1 arguments, got 2`.
