## How to Work

### Running Raskell

```bash
./rask                          # the REPL (:q to quit)
./rask --file program.rask      # run the program in a file
```

`./rask` recompiles the interpreter whenever a `.hs` file has changed. If your Haskell has a type error, GHC's message appears when you run `./rask` or `./run-tests`.

A program in a file is **one S-expression**, which can span many lines. A `;` starts a comment that runs to the end of the line.

### Tests

```bash
./run-tests                     # all the tests
./run-tests 02                  # just Stage 2 (the folder tests/02-control)
```

Each stage has a folder of tests, numbered to match the stages on this page (`tests/00-baseline` checks the features you start with). A test is a small `.rask` file whose first line says what output it expects. A test that expects `error` passes for any Raskell error message except `not implemented yet`. When a test fails, `run-tests` shows the program, what it expected, and what it got. The summary at the end gives a count for each stage. The stages are independent, so you can finish them in order and watch each one fill in. (Stages 5 and 6 need Stages 1 to 4, because your Raskell code uses those features.)

### The reference interpreter

The course server has a finished Raskell interpreter called **`rask-reference`**. It takes the same arguments as `./rask`:

```bash
rask-reference                              # its REPL
rask-reference --file program.rask          # run a file with it
./run-tests --reference                     # run the tests with it, instead of your code
./run-tests --reference 05                  # ...just Stage 5
```

Use it to answer "what *should* this do?" Whenever your interpreter does something that surprises you, run the same expression through `rask-reference`. If the two differ, the bug is in your Haskell. If they agree, the surprise is in your understanding of the language, or in your Raskell program.

That makes it especially handy in Stages 5 and 6. With `--reference`, you can test your Raskell library and your Collatz program before your interpreter is finished, and you know any failure is in your Raskell code.

## The Language

These are the rules for the finished language. The tests check them, and `rask-reference` follows them.

**Values.** Raskell has integers, the Booleans `#t` and `#f`, symbols, lists, and functions. The empty list `()`, the Boolean `#f`, and an error are three different things. Unlike some Lisps, Raskell never treats one as another.

**Printing.** A list prints in parentheses, as in `(1 (a b) #t)`. A symbol prints as its name. A function prints as `#<procedure>`, or `#<procedure:+>` for a primitive. An error prints as `error:` followed by a message.

**Function calls.** For a call `(f a b ...)`, Raskell evaluates `f` and **every** argument first (call by value), then applies the function. A function made with `lambda` must receive exactly as many arguments as it has parameters. Scope is lexical.

**Truth.** `if`, `cond`, `and`, `or`, and `not` accept **only** Booleans as tests. Using anything else, such as `(if 0 'a 'b)`, is an error. (Racket would treat `0` as true. Raskell is stricter.)

**Arity.** `+`, `-`, `*`, `quotient`, `modulo`, and the comparisons take **exactly two** numbers. `append` takes exactly two lists. (Racket allows more. Raskell keeps it simple.)

## Stage 1: Arithmetic and Comparisons (15%)

| Expression | Result |
| --- | --- |
| `(+ 3 5)` | `8` |
| `(- 3 10)` | `-7` |
| `(* 4 6)` | `24` |
| `(quotient 10 3)` | `3` |
| `(modulo 10 3)` | `1` |
| `(<= 4 4)` | `#t` |
| `(+ 1 'a)` | an error |
| `(quotient 1 0)` | an error |

Look at the primitives table. The entry for `+` is

```haskell
("+", arith "+" (+))
```

That's a partial application: `arith` takes the operation's name, a Haskell function on `Integer`s, and then the list of argument values. So `(+ 3 5)` runs `arith "+" (+) [VNumber 3, VNumber 5]`. `-` and `*` use `arith` too, so writing `arith` once gives you all three. The comparisons share `compareWith` the same way.

Implement `arith`, `compareWith`, `primQuotient`, and `primModulo`. `twoNumbers` does most of the checking for you.

**Integer division.** As in Racket, `quotient` rounds toward zero, so `(quotient -7 2)` is `-3`. `modulo` gives a result with the sign of the divisor, so `(modulo -7 2)` is `1`. Haskell has a function for each: look up `quot` and `mod`. Dividing by zero is a Raskell error. Don't let it become a Haskell crash.

## Stage 2: Booleans and Controlled Evaluation (20%)

| Expression | Result |
| --- | --- |
| `(not #f)` | `#t` |
| `(if (< 1 2) 'yes 'no)` | `yes` |
| `(if #t 7 (quotient 1 0))` | `7`, with no error |
| `(cond ((= 1 2) 'a) ((= 1 1) 'b) (else 'c))` | `b` |
| `(and #f (= 1 (quotient 1 0)))` | `#f`, with no error |
| `(or #t (= 1 (quotient 1 0)))` | `#t`, with no error |
| `(and)` / `(or)` | `#t` / `#f` |

`not` is an ordinary primitive, like the ones in Stage 1. The other four are **special forms**, and that's the point of this stage. A function call evaluates all its arguments before the function runs. `if` can't work that way: `(if #t 7 (quotient 1 0))` must give `7`, so `if` must never evaluate the branch it doesn't choose. The same goes for `cond`, `and`, and `or`. Each receives its parts as unevaluated `SExpr`s, and it decides which ones to evaluate, and when.

- **`if`** has exactly three parts: a test, a then-branch, and an else-branch. Evaluate the test, then evaluate **only** the chosen branch.
- **`cond`** has clauses of the form `(test result)`, tried in order. The result of the first clause whose test is `#t` is the answer, and later clauses aren't evaluated at all. An optional last clause `(else result)` matches anything. If no clause matches, it's an error. `condClauses` in `RaskAST.hs` reads the clauses for you, so you only write what they mean.
- **`and`** evaluates its parts left to right and stops at the first `#f`. **`or`** stops at the first `#t`. With no parts, `(and)` is `#t` and `(or)` is `#f`. Like `if`, they accept only Booleans.

## Stage 3: Local Bindings (10%)

### `let`

```racket
(let ((x 10)) (+ x 5))                    ; 15
(let ((x 2) (y 3)) (* x y))               ; 6
(let ((x 1)) (let ((x 2) (y x)) y))       ; 1
```

`let` evaluates each expression in the **current** environment, then evaluates its body with the names bound to the results. All the expressions are evaluated before any of the new names exist. That's why the last example gives `1`: inside the inner `let`, the `x` in `(y x)` still refers to the outer `x`.

You've seen this before. In [Module 5](../modules/05.1-environments-scope-closures.md#we-already-know-how-to-give-let-a-meaning), `let` turned out to mean the same thing as applying a function:

```racket
(let ((x 10) (y 20)) body)      means      ((lambda (x y) body) 10 20)
```

Implement `evalLet` by building that application as an `SExpr` and evaluating it. Don't write new code for environments. `bindingList` (in `RaskAST.hs`) checks the shape of the bindings and gives you a list of `(name, expression)` pairs.

### The provided `letrec`

Try this in the REPL once `let` works:

```racket
(let ((down (lambda (n) (if (= n 0) '() (cons n (down (- n 1))))))) (down 3))
```

It fails with `unbound identifier: down`. The `lambda` is evaluated in the environment **outside** the `let`, where `down` isn't bound yet, so the closure doesn't know its own name. That's lexical scope doing exactly what it should, and it means `let` can't define a recursive function.

`letrec` can:

```racket
(letrec ((down (lambda (n) (if (= n 0) '() (cons n (down (- n 1)))))))
  (down 3))                               ; (3 2 1)
```

Raskell's `letrec` binds exactly one name, to a `lambda`. It's **already implemented** in `RaskEval.hs`. You use it in Stage 6. Here's the heart of it:

```haskell
evalLetrec env [bindings, body] = do
    pairs <- bindingList "letrec" bindings
    case pairs of
        [(f, SList [SSymbol "lambda", paramList, fbody])] -> do
            params <- parameterList paramList
            let closure = VClosure env' params fbody
                env'    = Map.insert f closure env
            eval env' body
        ...
```

The closure needs to remember an environment in which `f` is bound to *the closure itself*. Look at the two `let` lines. `closure` is defined using `env'`, and `env'` is defined using `closure`. Each one is defined in terms of the other. In most languages that's nonsense, but in Haskell it works, because Haskell is lazy. Neither value is examined while it's being defined. The `Map.insert` just stores a reference to `closure` without looking inside it. When `f` is finally called, its body looks up `f` in `env'` and finds the very closure being run.

!!! question "Think about it"

    2. Suppose you translated `evalLetrec` line for line into a strict language like Python, where every definition is evaluated immediately. What would go wrong at the two mutually referring definitions? (Real interpreters for strict languages usually create the environment first, then *mutate* it to add the closure.)
    3. In [Module 08.3](../modules/08.3-self-application-recursion-fixed-points.md), you got recursion with no named functions at all, using the Y combinator. Try it in Raskell: define `Y` with a `let`, and use it to define factorial. What happens, and why? (Raskell uses call by value. If you get stuck, look up the **Z combinator**.)

## Stage 4: Lists and Higher-Order Functions (20%)

| Expression | Result |
| --- | --- |
| `(list 'a (+ 1 2) 'c)` | `(a 3 c)` |
| `(append '(a b) '(c d))` | `(a b c d)` |
| `(map (lambda (x) (* x 2)) '(1 2 3))` | `(2 4 6)` |
| `(map first '((a b) (c d)))` | `(a c)` |
| `(foldl (lambda (x acc) (+ x acc)) 0 '(1 2 3))` | `6` |
| `(foldl cons '() '(a b c))` | `(c b a)` |

`list` takes any number of arguments. `append` takes exactly two lists.

The interesting ones are `map` and `foldl`. Their first argument is a **Raskell function**. It might be a primitive like `first`, or a closure like `(lambda (x) (* x 2))`, which has a body that only the evaluator knows how to run. Your Haskell code can't call it directly. Use **`apply`**, the same function the evaluator uses for every function call, and it handles both kinds.

!!! warning "`foldl`'s argument order is Racket's, not Haskell's"
    Raskell follows Racket: `(foldl f init xs)` calls `f` with the **element first** and the **accumulator second**.

    ```racket
    (foldl f init '(a b c))   =   (f c (f b (f a init)))
    ```

    Haskell's `foldl` passes them the other way around. So `(foldl cons '() '(a b c))` is `(c b a)`, and `(foldl (lambda (x acc) (- x acc)) 0 '(1 2 3))` is `2`. Check that one by hand.

## Stage 5: A Library Written in Raskell (10%)

Raskell doesn't have `reverse` or `filter`. You could add them to `RaskEval.hs` as more primitives, but you won't. Instead, you write them **in Raskell**, using the features you just built.

| Expression | Result |
| --- | --- |
| `(reverse '(a b c))` | `(c b a)` |
| `(reverse '())` | `()` |
| `(filter (lambda (x) (< x 4)) '(1 5 3 7 2))` | `(1 3 2)` |

`filter` keeps the elements in their original order.

Your definitions go in `rasklib/list-library.rask`. Raskell has no global `define`, so a library is a file holding one list of definitions:

```racket
( (reverse (lambda (xs) ...))
  (filter  (lambda (keep? xs) ...)) )
```

`--lib` loads a library in front of a program:

```bash
./rask --lib rasklib/list-library.rask --file some-program.rask
./rask --lib rasklib/list-library.rask          # a REPL with the library loaded
```

The definitions load in order, so a later one can use an earlier one. A definition whose value is a `lambda` can also call itself, as if it were bound by `letrec`.

Raskell has no way to test whether a list is empty, so a recursive definition that walks down a list won't get far. Use the higher-order function you already have. `foldl` visits every element, in order, and you decide what to build. One of the examples in Stage 4 is most of `reverse` already.

## Stage 6: Collatz in Your Own Language (25%)

Here's the Collatz rule, one last time. Starting from a positive integer `n`:

- if `n` is even, the next number is `n / 2`;
- if `n` is odd, the next number is `3n + 1`.

Repeat until you reach `1`. (Nobody has proved that every starting number gets there. Every number anyone has tried does, including all the ones we test.)

`programs/collatz.rask` is a single S-expression whose **value is a function** of `n`. That function returns a list of four things about the sequence starting at `n`:

```racket
(sequence  length  even-elements  reversed-sequence)
```

For `n` = 6:

```racket
((6 3 10 5 16 8 4 2 1) 9 (6 10 16 8 4 2) (1 2 4 8 16 5 10 3 6))
```

When the program's value is a function, the file runner applies it to each number you give on the command line:

```bash
./rask --lib rasklib/list-library.rask --file programs/collatz.rask 6 7
```

The starter file gives you the program's shape, with `'TODO-...` symbols to replace. Work through it in this order.

**Milestone A: one step.** Write `next`, which takes `n` to the next number in the sequence. Use `modulo` to decide whether `n` is even and `quotient` to halve it. Test it on its own in the REPL before moving on.

**Milestone B: the whole sequence.** Write `collatz`, using `letrec`, so that `(collatz n)` is the list of numbers from `n` down to and including `1`:

```racket
(collatz 6)   ; (6 3 10 5 16 8 4 2 1)
(collatz 7)   ; (7 22 11 34 17 52 26 13 40 20 10 5 16 8 4 2 1)
(collatz 1)   ; (1)
```

**Milestone C: analyze it with your library.** Fill in the other three fields of the result. Use `foldl` for the length, `filter` for the even elements, and `reverse` for the reversed sequence. All three use the functions from Stages 4 and 5. Don't write new recursion for them.

**Milestone D: run it.** Run the file on several inputs, then run the tests.
